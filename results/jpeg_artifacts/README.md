# Clip-art JPEG 去伪影与指标实验

本轮实验由智能体执行，成员 B 为蒋天乐（2023010721）；成员人工核验待完成。实际运行目录为 [jpeg-20261117T155122Z-e37cd961efa5](jpeg-20261117T155122Z-e37cd961efa5)。两个干净输入 × JPEG 质量 {10,30,70} × λ={0.0005,0.002,0.008,0.03}，共 24 次 L0 平滑，固定 κ=2、βmax=100000。没有筛除低分结果，使用现有 `run_and_save` 调用本组核心，未使用完整第三方 L0 接口。

## 输入、参数与指标口径

干净真值见 [输入来源](../../data/jpeg_artifacts/README.md)：程序生成的小屋 RGB 与灰度线图，256×256，无随机过程。JPEG 质量、4:4:4 RGB 采样及量化表保存在各组 `jpeg.json`；每组的 `compressed.jpg` 是真实 JPEG 文件，不是文件扩展名伪装。实验文件夹另存 `clean.png`、源清单和 SHA-256，迁移仓库后依旧可核对。

所有 JPEG 基线和恢复图都与同一干净 PNG 比较，主表口径为 **解码后的8位图像**：JPEG 原解码像素，以及 `output.npy` 裁剪到 [0,1] 后乘255、四舍五入保存的 `output.png`。未裁剪 float64 NPY 仍保留，不与主表混用。8位口径便于指标对应实际展示图，不意味着裁剪不存在影响。

- PSNR：`10*log10(255²/MSE)`，MSE 全像素、全通道平均。
- SSIM：11×11 高斯窗、σ=1.5、K1=.01、K2=.03、data_range=255、总体矩，计算有效内域并排除5像素边界；RGB 三通道分别计算后等权平均，不转亮度、不下采样。参考 [原作者公式](https://www.cns.nyu.edu/~lcv/ssim/)，RGB口径是本组约定，不能直接与其他亮度或下采样实现的数值混用。
- `metrics.csv` 的 `psnr_db/ssim` 为全图；`roi_psnr_db/roi_ssim` 是对固定同一裁剪重新计算的局部值；局部 SSIM 也排除裁剪本身的5像素边界。`delta_*` 相对同图同质量的 JPEG 基线。
- 全图与局部图依次为干净图、JPEG、四个 λ，均标注参数。**局部图顶部的 PSNR/SSIM 仍为全图指标**，局部指标需看 CSV；所有局部以相同 ROI 最近邻放大，避免缩放插值掩盖伪影。全图中的红框只用于指示 ROI。

下面按每种输入／质量列出 JPEG 基线与网格内全图 PSNR 最大的一组；这不是用独立验证集选出的通用参数。完整24组、局部指标和差值见 [metrics.csv](jpeg-20261117T155122Z-e37cd961efa5/metrics.csv)。

实际查看局部图后的智能体观察：

- **正例，小屋 Q10／Q30**：JPEG 在屋檐与窗框周围出现色带、平坦区域出现条纹；增大 λ 后，窗框附近的条纹和部分块状变化减少，窗户主轮廓仍可辨。Q30 的 λ=.008 从 30.9931dB／.931767 提升到 31.9893dB／.965178；继续增大到 .03 后全图指标回落，说明平滑力度不是越大越好。Q10 的 λ=.03 仍有色偏与边界位置误差，不能宣称恢复为干净图。
- **失败例，灰度线图 Q70**：压缩本来已较轻，λ=.03 把右上低对比横线和小竖线抹去；圆形与斜线仍在，但细节损失明显。全图 39.1555dB／.983487 降为 27.5480dB／.945320；对应局部 PSNR=28.1140dB、SSIM=.814657。较大的 L0 惩罚没有区分伪影与真正的小梯度结构。
- **指标与局部不完全一致**：灰度 Q10 的 λ=.008 全图 PSNR 在该质量网格中最大，而 λ=.002 的 SSIM 更高；同样 λ=.002 时，Q30 全图 SSIM 提升 .010510，但 PSNR 下降 .1760dB。彩色 Q70 的 λ=.03 全图 SSIM 比 JPEG 仍高 .001129，PSNR 却下降 1.6677dB。不能用一个指标或更少的细线直接宣布图像更好。
- 24组中有 **8组 PSNR 低于 JPEG、5组 SSIM 低于 JPEG**。这些全部保留在表格和图板中。小 λ 对重度压缩可能去伪影不足；大 λ 对轻度压缩易过度平滑。只在本次合成图和参数网格内得出这些结论，未证明对一般 Clip-art 最优。

## 实际运行与验证

项目根目录执行（本轮 Python 路径是临时环境；换机使用安装依赖后的 `python`）：

```bash
/tmp/media-compute-venv/bin/python -m scripts.jpeg_artifacts prepare
/tmp/media-compute-venv/bin/python -m scripts.jpeg_artifacts run
/tmp/media-compute-venv/bin/python -m scripts.jpeg_artifacts check results/jpeg_artifacts/jpeg-20261117T155122Z-e37cd961efa5
/tmp/media-compute-venv/bin/python -m unittest discover -s tests -v
```

`run` 每次新建独立目录，不覆盖旧结果。`experiment.json` 记录实际命令、环境、全组参数、指标协议和产物 SHA-256；各 `run.json` 记录输入副本、参数、迭代、核心耗时及环境。24次核心耗时约0.058–0.363秒，迭代21–27轮；耗时为本机单次观测，不含图板与指标计算，不能据此承诺其他机器速度。实际 Python3.10.12、NumPy2.2.4、Pillow11.3.0、OpenCV4.13.0；版本与成员A既有记录不同，但未改写其记录。

`check` 校验完整30行网格、源图／JPEG／全部输入输出／CSV与图板摘要，逐行重算全图和局部指标，检查真实 JPEG 格式、采样和量化表，核对运行参数、迭代耗时、输入像素、NPY形状／有限值及PNG量化关系；最后对两幅 Q30、λ=.002 抽查重跑。首次记录 [checks.json](jpeg-20261117T155122Z-e37cd961efa5/checks-20261117T155153Z-cf79f5edeb1b/checks.json) 通过：两组浮点误差0、显示像素差0。重复 `prepare` 验证原始像素不变；在临时复制品上删除JPEG、篡改CSV和NPY，三次均被检查拒绝，见 [正负验证记录](verification-20261117T155416Z-4f67e314feae/checks.json)。14项自动测试通过，其中4项指标验证使用常数闭式和直接逐窗口高斯加权矩作独立计算。所有检查是智能体执行验证；成员应在展示环境再运行并自行观察。

本次没有下载图像，没有用论文输出作真值，没有运行作者完整L0实现。公开来源仅用于指标定义；算法核心及成员A的既有实验保持原状。
